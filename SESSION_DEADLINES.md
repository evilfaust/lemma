# Время попыток и строгий срок сдачи

Версия: 3.9.426, 02.11.2026.

Колонка «Время» в «Результатах» показывает даты начала и сдачи, а ниже — разницу
между ними с учётом перерывов. Полные даты видны в подсказке в часовом поясе
устройства учителя. Карточка ученика и раздел «Прогресс» используют тот же
интервал для истории и среднего. В среднее входят завершённые онлайн-попытки
с обеими отметками. Бумажный бланк в «Результатах» помечается «Бланк».

## Срок сдачи

В панели выдачи рядом с датой — «Строгий срок»:

- Выключен (включая старые выдачи): дедлайн остаётся ориентиром; сдача позже доступна.
- Включён: в момент дедлайна запрещаются начало новой попытки, отправка уже
  начатой и запись ответов. Без даты ограничение не действует.
- Учитель может продлить срок, выключить строгий срок, внести бланк и исправить балл.
  Ручной переключатель приёма остаётся отдельной настройкой.

Клиент проверяет срок перед началом и отправкой, обновляет настройки раз в 10 с
и при возврате на вкладку. При истечении срока показывает сообщение; локальный
черновик сохраняется. Просмотр уже сданного результата остаётся доступным.
Сервер проверяет актуальную выдачу своим временем при создании/изменении попытки
и ответа (в том числе через REST/batch), поэтому старая вкладка ограничение не обходит.
Автоматической сдачи по таймеру нет.

## Хранение времени

- `attempts.started_at`: серверная отметка старта. Для новой попытки ученика —
  создание; для заранее выданной учителем — первое открытие учеником.
- `attempts.submitted_at` и `duration_seconds`: сервер фиксирует при сдаче.
- Для старых онлайн-попыток миграция заполняет только новое started_at из created.
  Более точное начало и ранее потерянную длительность восстановить нельзя.
- В старых попытках таймер начинал отсчёт заново при повторном открытии страницы,
  поэтому сохранённое duration_seconds могло отражать только последний заход.
  Отчёты считают интервал по отметкам, включая старые попытки.
- До миграции интерфейс использует created как запасной источник.

## Выкладка

1. Свежий бэкап VPS и проверка архива.
2. Миграция `pocketbase/pb_migrations/1789800000_strict_session_deadline.js`.
3. Оба файла `pocketbase/pb_hooks/session_deadline*` и перезапуск pocketbase-ege.
4. Учительский и ученический фронтенды одной версии.
5. Проверка миграции/полей, журнала запуска, здоровья API, публичных version.json
   и соответствия опубликованных файлов сборке. Браузер проверяет пользователь.

Миграция добавляет поля, сохраняет существующие результаты и не включает строгий
срок для старых выдач. Откат базы поверх боевых данных для этой выкладки не нужен.
