# Метод интервалов — эксперимент в лаборатории

Статус на 05.11.2026. Семь шагов в production, релиз `3.9.430-20261105052729`.
Обновлены серверная часть и оба фронтенда. Схема базы прежняя.
Вход учителя: https://l.oipav.ru/app/lab/intervals.

## Назначение и границы тренажёра

Самостоятельная сущность «Пошаговая работа»: свой набор заданий, назначение
и результаты. Учитель открывает «Лаборатория → Метод интервалов · эксперимент»
(`/app/lab/intervals`). Обычные генераторы, банк задач, выдачи тестов,
журнал, достижения и профиль слабостей эксперимент не использует.

Переиспользуется математическое ядро `utils/intervalMethod.js` и тип множества
решений из `quadraticInequality.js`; генерация эксперимента находится отдельно,
в `utils/lab/intervalExperiment.js`, и не вызывает хуки существующих генераторов.

- 3–20 заданий: произведения линейных множителей, дроби, чётные кратности.
- Целые критические точки −6…6; строгие и нестрогие знаки, отрицательные
  коэффициенты, пустой ответ и отдельные точки поддерживаются.
- Семь действий на одной прямой. Ученик находит корни, расставляет их,
  отмечает чётную кратность знаком `!`, закрашивает или выкалывает точки,
  расставляет знаки, штрихует промежутки и записывает ответ.
- На прямой сохраняются подтверждённые отметки. Закрашенные точки входят
  в ответ, поэтому на шаге штриховки выбираются только промежутки.
- Можно исправить ошибку и продолжить. Если помощь включена, после трёх ошибок
  на шаге доступен его показ. Учитель видит подсказки и показы по отдельности.
- При открытии уже выданной работы сервер возвращает новый порядок шагов.
  Начатая попытка продолжится с первого непроверенного шага текущего примера.
  Прежняя история и завершённые результаты доступны в отчёте.
- Рациональные дробные и иррациональные границы, разложение трёхчленов,
  адаптивные уровни и рейтинги — вне первой версии.

## Как провести пилот

1. Учитель создаёт работу, выбирает одну тестовую учебную группу, объём,
   типы заданий и подсказки. Курсы в первой версии не предлагаются.
2. Состав загружается штатным `api.getStudentsByGroup`, включая исторический
   состав по правилам проекта. До назначения можно раскрыть список учеников.
3. «Предпросмотр заданий» фиксирует случайный набор. Учитель может раскрыть
   условия и ответы или сгенерировать новый набор.
4. «Назначить группе» создаёт отдельную работу. Она появляется в кабинете
   только у зафиксированных участников. Прямая ссылка также требует входа
   назначенного ученика: `/student/lab-interval/{id}`.
5. Проверенные шаги и ошибки сохраняются на сервере, черновик текущего
   непроверенного ввода — только на устройстве. После сетевой ошибки нужно
   загрузить сохранённое состояние; повторная отправка вслепую заблокирована.
6. Учитель открывает «Результаты и ссылка»: состав, статусы, самостоятельно /
   после исправлений / с подсказкой / пропущено, ошибки и подсказки по шагам.
   В деталях ученика — последние 10 проверок каждого шага, полные счётчики
   и правильный ответ для разбора.
7. «Закрыть тренировку» запрещает старт и отправку шагов, сохраняя результаты.
   Закрытую работу можно открыть снова. Автооценок в журнале нет.

Состав — снимок учеников, а не вычисляемое каждый раз членство. Поэтому перевод
учебного года не отнимает доступ, а новые участники группы не подключаются
автоматически. Для другого состава или набора заданий создаётся новая работа.
Одна попытка на ученика в работе; повторная тренировка — новая работа.
Один снимок заданий общий для участников конкретной работы.

## Хранение и доступ

Миграция: `pocketbase/pb_migrations/1789900000_lab_interval_experiment.js`.

- `lab_interval_works`: owner, group, participants, снимок roster/tasks/settings,
  title, is_open, даты. Исходное выражение и эталоны шагов сохраняются в tasks.
- `lab_interval_attempts`: work, student, state, status, даты. Уникальная пара
  `(work, student)`. State содержит текущие позиции, revision, проверки и подсказки.
- Все стандартные CRUD rules обеих коллекций закрыты (`null`), включая чтение.
  Работа идёт через `lab_interval.pb.js` + `lab_interval_lib.js`.
- Учительские API проверяют коллекцию авторизации, секцию lab, роль,
  владельца работы и доступ к выбранной группе. Создание/закрытие пишут audit_log.
- Ученические API проверяют явный список participants при каждом запросе.
  Ученик получает только данные текущего примера. В режиме разбора сервер
  показывает решение текущего шага. Старый клиент получает запрос обновить страницу.
- Проверка шага, статистика и продвижение выполняются сервером в транзакции.
  Revision отклоняет повторную или конкурентную отправку с кодом 409.
- `GET /api/lab-interval/my` — отдельная лента. Обычные ленты не менялись.
  До установки backend отсутствие маршрута скрывает блок в кабинете;
  учителю показывается сообщение о неподключённом сервере эксперимента.

## Проверки и выкладка

```bash
cd ege-tasks
npx vitest run src/__tests__/labInterval*.test.*
npm run build
```

API-проверка на настоящем PocketBase той же версии, с синтетическими
пользователями и временной БД (каталог автоматически удаляется):

```bash
POCKETBASE_BIN=/path/to/pocketbase node pocketbase/tests/lab-interval.integration.mjs
```

Скрипт не обращается к VPS, не читает production-секреты и не копирует БД.
Проверяет миграцию, роли, чужого учителя/ученика, закрытые CRUD, защиту
эталонов, прохождение, историю, ревизии (включая конкурентные запросы),
подсказки, пропуски, отчёт и закрытие/открытие работы.

Проверено локально: 106 тестов в 11 файлах, включая обычный кабинет и прежний
генератор; 400 сгенерированных заданий сверены подстановками внутри
математического теста; 74 проверки API на PocketBase 0.36.4; production build
3.9.429. Проверка ESLint недоступна: в проекте не установлены его зависимости
(`@eslint/js` и плагины); состав зависимостей не менялся.

При выкладке нужны новая миграция и два новых backend-файла,
затем оба фронтенда. Перед работой с production следовать DATABASE_SAFETY.md;
старые миграции и посторонние изменения из рабочего каталога не включать
в выкладку автоматически. Down удаляет только две коллекции эксперимента
со всеми попытками и требует процедуры для деструктивных операций.

Первая выкладка, версия 3.9.429, проверена 05.11.2026:

- Свежий архив `backup_2026-11-05_01-26-00.tar.gz`, 376475234 байта;
  проверены data.db, auxiliary.db, vec.db и 62280 записей storage.
- На VPS до выкладки не было ожидающих миграций. Применена только новая;

- SHA-256 всех трёх новых backend-файлов совпали с локальными.
  PocketBase и backend helper активны; публичные health-эндпоинты отвечают 200.
